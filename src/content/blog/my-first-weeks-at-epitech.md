## A different way to learn

Starting my first year at [EPITECH Nancy](https://www.epitech.eu/) was a big change. I was used to learning through classes and then applying what I had seen. At EPITECH, projects quickly become the starting point: you receive a goal, explore what you need to learn, and build a solution yourself.

The C pool was my first real experience of that approach. It is an intense introduction to programming in C, where each exercise adds a new concept and the next one expects you to reuse what you have already learned.

## From small functions to real programs

The beginning focused on the fundamentals: strings, character checks, and functions such as `strcmp` and `strstr`. Then the exercises grew into a small library, word parsing, arrays, structures, and operations on linked lists.

That progression changed how I looked at a problem. A function that seemed simple could involve careful pointer handling, memory ownership, or an edge case I had not considered. When a test failed, I had to trace the data through my own code instead of relying on a complete example from a course.

Later tasks brought those pieces together in small command-line programs such as `cat` and `grep`. At that point, I was no longer implementing only isolated functions: I had to think about input, errors, output, and how the parts of a program fit together.

## Learning to work with constraints

The pool also made tools like the compiler, Makefiles, and tests part of my everyday routine. I learned to read compiler warnings, build one piece at a time, and use tests to check both expected results and awkward edge cases. Coverage goals pushed me to ask what my code did when it received empty input, invalid data, or a boundary value.

There was a lot to absorb, and getting stuck was part of the process. The useful habit was to make the problem smaller: understand the input, write down what the function should guarantee, and test one case at a time. Each exercise became easier to approach once I stopped trying to solve everything in one go.

## What I took away

My first weeks at EPITECH taught me that learning to program is also learning how to find your way through an unfamiliar problem. The C pool gave me a demanding first step: pointers, memory, tests, and debugging stopped being abstract topics and became things I had to use to make a program work.

I still have a lot to learn, but I now feel more comfortable opening a subject, breaking it down, and building an answer one step at a time.

> “The pool was not just my first set of C exercises. It was my first lesson in learning by building.”
